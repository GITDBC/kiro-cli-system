# What's new in CLI V3

> CLI V3 runs the unified agent harness in your terminal. What changed from 2.x, breaking changes, step-by-step migration, and new features.

**ℹ️ Info:** An early release of Kiro CLI V3 is now available. Use `kiro-cli --v3` for interactive CLI sessions. ACP clients use `kiro-cli acp --agent-engine=v3 --auth-method=cli`; see [Migrate an ACP client to CLI V3](https://kiro.dev/docs/cli/v3/acp-migration.md). V3 runs alongside your existing 2.x install, and your current setup is unchanged until you opt in.

## A single harness for all Kiro surfaces

CLI V3 uses the same [unified agent harness](https://kiro.dev/docs/how-kiro-works.md) as Kiro IDE and Kiro Web. This brings shared agent-loop improvements to the terminal and lets supported `.kiro` configuration travel between surfaces. Some tools, commands, and configuration fields remain surface-specific; the tables below identify the supported V3 path.

## What's new in V3

**Spec-driven development**: The Spec agent brings structured development to the terminal. Define requirements, generate designs, execute task plans. Use `/spec new <name>` to start. [Learn more →](https://kiro.dev/docs/specs.md)

**Capability-based permissions**: Declare structured policies in `permissions.yaml` for fine-grained, auditable control. One rule can allow or deny an entire category of operations across all tools. [Learn more →](https://kiro.dev/docs/permissions.md)

**Enhanced hooks**: Standalone `.kiro/hooks/*.json` files with two action types (shell commands and agent prompts), new triggers, and a versioned schema. [Learn more →](https://kiro.dev/docs/hooks.md)

**Enhanced agent config**: Tag-based tool selection, unified permissions block, Markdown format, inline MCP servers. [Learn more →](https://kiro.dev/docs/custom-agents.md)

**Introspect subagent**: Ask Kiro about its features and get documentation-grounded guidance inline. It can explain capabilities, help with custom agents, Hooks, and Steering, and suggest configuration for your workflow. [Learn more →](https://kiro.dev/docs/cli/v3/new-features.md#introspect-subagent)

**Tangent**: Branch your conversation into side-conversations that inherit your context, explore freely, then jump back to exactly where you left off. Use `/tangent` to branch. [Learn more →](https://kiro.dev/docs/cli/v3/tangent.md)

## Breaking changes

| Change | Previous (2.x) | New (V3) | Impact |
|--------|----------------|-----------|--------|
| Built-in AWS tool unavailable | CLI 2.x `use_aws` tool (preferred alias `aws`) | Use MCP servers for AWS access | High |
| Session format changed | V2 session store | V3 session store (not backward-compatible) | High. Use `--v2` when you need to return to a V2 session |
| Hook format changed | CamelCase object embedded in the profile | PascalCase array definitions, inline or in standalone `.kiro/hooks/*.json` files | High |
| Hook trigger names | camelCase (`agentSpawn`) | PascalCase (`SessionStart`) | High |
| Persistent trust configuration changed | Per-tool `toolsSettings` rules | Capability-based `permissions.yaml`; session-wide trust uses `--trust-all-tools` or `/tools trust-all` | High |
| "Vibe" concept removed | N/A for CLI | "Default" mode is the standard name | Low |

## Migration guide

Start V3 and run `/upgrade-agent` to convert supported agent fields, permissions, and object-form Hooks. Then review its diagnostics and make only the manual changes it reports or your workflow requires. Run it again after you change V2 trust settings so the generated V3 rules stay current.

- [Full migration guide](https://kiro.dev/docs/cli/v3/migration-guide.md): all 7 steps with examples
- [Permissions migration](https://kiro.dev/docs/cli/v3/permissions.md): CLI 2.x trust configuration → `permissions.yaml`, behavioral changes
- [Hooks migration](https://kiro.dev/docs/cli/v3/hooks-migration.md): legacy object Hooks → profile-scoped arrays or standalone `.kiro/hooks/` files, trigger name mapping
- [ACP client migration](https://kiro.dev/docs/cli/v3/acp-migration.md): update ACP clients from the CLI v2 server to CLI V3
- [Agent config changes](https://kiro.dev/docs/cli/v3/agent-config.md): new fields and Markdown format
- [New features](https://kiro.dev/docs/cli/v3/new-features.md): plan mode, powers auto-pickup, skills, compaction, trusted workspaces, built-in tools

**ℹ️ Info:** Run `/upgrade-agent` inside a V3 session. See [Upgrading agent configs](https://kiro.dev/docs/cli/v3/upgrade-agent.md) for conversion behavior and diagnostics.

### Switch from the startup offer

When you start an interactive V2 chat, Kiro CLI may offer to switch you to V3. The offer has three options:

| Option | What happens |
|--------|--------------|
| **Switch to V3 and upgrade my configs** | Starts this session in V3, saves `chat.agentEngine` as `v3`, and upgrades your agent configs now and on later launches |
| **Remind me later** | Keeps this session in V2 and shows the offer again in about seven days |
| **Don't ask again** | Keeps this session in V2 and stops the offer |

Pressing Esc works like **Remind me later**. **Remind me later**, **Don't ask again**, and Esc leave your harness unchanged. You can still start V3 at any time with `kiro-cli --v3`.

## Remaining differences from V2

V3 does not reproduce every legacy surface. These differences remain relevant when deciding whether to switch:

| Difference | V3 behavior | If you depend on the V2 behavior |
|------------|-------------|----------------------------------|
| **Classic interface** | The V3 harness runs in the terminal UI, not the legacy non-TUI interface | Continue using the classic interface until your workflow works in the terminal UI |
| **Workspace checkpoints** | The experimental `/checkpoint` feature remains classic-only; V3 provides `/rewind` for conversation branches | Use version control to restore files and `/rewind` to revisit an earlier turn |

V3 can resume its own sessions through `/sessions`, `--resume`, and `--resume-id`. V2 cannot open a V3 session because the stored session formats differ; that is a cross-version migration boundary, not a missing V3 resume capability.
